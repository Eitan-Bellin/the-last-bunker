# 03 · עדשה 3: לוגיקה ונכונות קוד

**סיכום (3 שורות):**
1. הליבה יציבה: 42 תרחישי מצב קיצוני (0 עובדים, 0 משאבים, ימים 1000 ו-100,000, רמות 0 ו-99999) על 3 שמירות אמיתיות לא הפיקו NaN, שליליים או קריסה. החריג היחיד: NaN שנכנס למורל מרעיל את כל הכלכלה.
2. נמצאו שני באגי לוגיקה אמיתיים ברי-שחזור: עובד שנתקע לנצח על "הריסה" שכבר נוקתה (כשיצא למשלחת), ומנהל העבודה שמפסיק לאייש הכל כש"חדר אטום" הוא היעד הראשון. בנוסף: חדר האזכרה לא ניתן לבנייה למי שלא איבד אף אחד, והסבר המורל בפאנל אנשים חסר את כיפת השמיים.

## בדיקות שעברו נקי (ללא ממצא)

- **סדר מערכות:** `resource → building → population → event → research → exploration → restoration → incident → family → project → dig → act → threat → contracts → outposts → foreman → homes → maintenance → inbox → achievements → objective → era → story → daily` (`GameEngine.registerSystems`). לא נמצאה תלות מעגלית; `InfraSystem` אינו מערכת (פונקציות טהורות שנקראות מ-Incident/Resource). הערה: הכוח המכפיל מעל cap נקבע ב-tick הקודם (מכאן אין אובדן פרסי הישגים: נבדק `ach1.mjs`, כל 5 הפרסים במטבעות המערכה הגיעו).

- **דלתות מחיצה:** ניקוז חשמל 0.2 לדלת: 34-49 דלתות אטומות = 6.8-9.8 לשנייה מול עודף 24-2,800 לשנייה; אין ספירלה (`door1.mjs`). החשש מדלת אטומה שמנתקת חדר מחשמל/אוכל לא מתממש: `isSealedOff` משפיע רק על שיבוץ חדש (`PopulationSystem.ts:422`) ולא על ייצור (ולכן אין "אנשים תקועים": אין לוגיקת הליכה ב-state). הפונקציות `isShutOff`/`allDoors`/`removeDoor` מתות, כך שאי אפשר גם להסיר דלת (רק לפרק חדר שמצמידה אותה: `pruneOrphanDoors`).
